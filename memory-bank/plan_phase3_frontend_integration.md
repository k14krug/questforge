# Phase 3 Implementation Plan: Real-Time Communication & Frontend Integration

## Overview
This document outlines the implementation plan for Phase 3 of QuestForge development, focusing on real-time communication and frontend integration. This plan assumes no prior knowledge of Phases 0-2.

## Dependencies from Previous Phases
### Phase 0: Specification & Setup
- Database schemas: See `models.py` for implementation
- API endpoints: Defined in `routes/games.py` and `routes/templates.py`
- Socket.IO events: Defined in `app.py` (search for `socketio.on` decorators)
- AI model config: Located at `config.json` in project root
- Error handling: Implemented in `services/error_handler.py`
- Map schema: Defined in `memory-bank/interactive_map_schema.md`

### Phase 1: Core Backend
- Authentication: Implemented in `routes/auth.py`
- Template CRUD: See `routes/templates.py`
- Game creation: See `services/game_creation_service.py`
- Character sheet: JSON structure in `models.py` (GamePlayer model)
- Cost tracking: Implemented in `services/cost_service.py`

### Phase 2: Game Logic & AI
- Campaign Charter: Generated by `services/campaign_service.py`
- Action resolution: Implemented in `services/action_resolution.py`
- NPC memory: Condensed by `services/ai_service.condense_npc_memory()`
- Real-time comms: See `app.py` Socket.IO implementation
- AI integration: See `services/ai_service.py` for model calls

## Integration Points (with Implementation References)
1. **Socket.IO Events**  
   - Listeners in `static/js/main.js` for:
     - `skill_check_initiated`: Triggers dice roller UI
     - `dice_roll_result`: Updates game log with roll outcome
     - `npc_memory_update`: Refreshes NPC cards
   - Action emission: `submit-action-btn` handler in `play_page.html`

2. **GameState API**  
   - `/api/character_sheet`: See `routes/games.py#get_character_sheet`
   - `/api/npcs`: See `routes/npcs.py#get_npcs`
   - `/api/map`: See `routes/world.py#get_map_data`

3. **Campaign Charter Integration**  
   - Access via `game.campaign_charter` in templates
   - NPC rendering: `templates/play_page.html` NPC cards
   - Map rendering: Uses `charter.world_map` structure

## Required Context for AI Agent (File Locations)
- `config.json`: Project root directory
- `character_sheet.json`: Structure defined in `models.py` (GamePlayer model)
- `campaign_charter.schema`: Defined in `services/campaign_service.py`
- `socket_events.md`: `memory-bank/socket_io_events.md`

## Implementation Priorities
1. Complete Play Screen UI with tabbed information panel
2. Implement visual dice roller overlay
3. Integrate real-time event handling
4. Develop backend API support for frontend data
5. Implement NPC management system with real-time updates

## Detailed Implementation Steps

### 1. Play Screen UI Enhancement
**Dependencies**: Game model settings (Phase 1), Campaign Charter (Phase 2)  
**Integration**: Socket.IO events (Phase 2), Character sheet API (Phase 1)

### 2. NPC Management System
**Dependencies**: NPC generation (Phase 2), Memory condensation rules  
**Integration**: NPC data API, Socket.IO updates

### 3. Visual Dice Roller
**Dependencies**: Game settings (`enable_visual_dice_roller` flag)  
**Integration**: `skill_check_initiated` event, character sheet bonuses

### 4. Real-Time Event Handling
**Dependencies**: Socket.IO implementation (Phase 2)  
**Integration**: Event listeners for game state updates

### 5. Backend API Support
**Dependencies**: API endpoints (Phase 0)  
**Integration**: Data fetching for frontend components

### 6. Testing Strategy
**Dependencies**: Error handling (Phase 0)  
**Integration**: End-to-end test all integration points

  - Party & NPCs
