# Comprehensive Implementation Plan: Puzzle Mechanic

**Overall Strategy:**

Our strategy is built on a foundation of **phased, incremental development**, protected by **feature toggles**, ensuring **backward compatibility**, supported by **robust, targeted testing** at each step, and maintained with **clear, continuous documentation**. This approach minimizes risk and allows for precise control over the rollout.

#### Phase 1: Core Data Model & AI Generation (Backend Only)

**Goal:** Establish the foundational data structures for puzzles within templates and games, and enable the AI to generate puzzle definitions as part of the campaign, without affecting existing gameplay logic or player UI.

*   **Changes:**
    *   **`questforge/models/template.py`:** Extend the `default_rules` JSON field to include a `puzzles` object. This object will define `enabled_types`, `difficulty_settings`, `global_puzzle_difficulty`, `hint_frequency`, and `failure_consequences` as template defaults.
    *   **`questforge/models/game.py`:** Extend the `template_overrides` JSON field to allow game creators to override the template's puzzle settings.
    *   **`questforge/models/campaign.py` / `questforge/models/game_state.py`:** Determine the best place to store the *generated* puzzle definitions (e.g., `puzzle_id`, `type`, `description`, `solution_criteria`, `plot_point_id`, `initial_state_changes`, `completion_state_changes`, `clues`, `failure_consequences`, `skip_option`, `skip_consequences`). This will likely be within `Campaign.state_data` or `GameState.state_data` as a structured list/dictionary.
    *   **`questforge/utils/prompt_builder.py`:** Update `build_campaign_prompt()` to include the merged puzzle configuration (from template defaults and game overrides) in the prompt sent to the main AI (GPT 4.1). This prompt will instruct the AI to generate specific puzzle instances within the campaign structure.
    *   **`questforge/services/ai_service.py`:** Implement a new method, `check_puzzle_solution()`, which will take a puzzle definition, current game state, and player action, and use GPT 4.1 mini to evaluate if the solution criteria are met. This method will return `{"solved": true/false, "confidence_score": X}`. This method will *not* be called by the main game loop yet.
    *   **`config.py`:** Add a feature flag, `ENABLE_PUZZLES = False`, to control all new puzzle-related logic.
*   **Cline AI Agent's Actions:**

    2.  `replace_in_file` to add the `puzzles` structure to `default_rules` and `template_overrides` in `template.py` and `game.py`.
    3.  `replace_in_file` to update `prompt_builder.py` to include puzzle configuration in the campaign generation prompt.
    4.  `replace_in_file` to add the `check_puzzle_solution()` method to `ai_service.py`.
    5.  `replace_in_file` to add `ENABLE_PUZZLES = False` to `config.py`.

*   **Testing (Cline's Responsibility):**

    3.  Manually trigger campaign generation (if possible via existing admin tools or a temporary script) and inspect the generated campaign/game state data to confirm puzzle definitions are being generated by the AI as expected.
    4.  Unit test the new `ai_service.check_puzzle_solution` method with various mock inputs to ensure it returns expected `solved` and `confidence_score` values.

#### Phase 2: Backend Integration & Gating (Hidden from Player UI)

**Goal:** Integrate the puzzle resolution logic into the game's action processing loop and link it to plot points, ensuring progression is blocked by puzzles. This phase remains hidden from the player's view.

*   **Changes:**
    *   **`questforge/services/socket_service.py`:** Modify `handle_player_action()` to:
        *   Check if `ENABLE_PUZZLES` is `True`.
        *   If true, retrieve `active_puzzles` from `GameState.state_data`.
        *   If active puzzles exist, call `ai_service.check_puzzle_solution()` with the player's action and the relevant puzzle definition.
        *   Based on the `solved` status and `confidence_score`, update the puzzle's status in `GameState.state_data['active_puzzles']` and apply `completion_state_changes` or `failure_consequences`.
        *   Implement the core logic to prevent associated plot points from being marked as `completed` if their gating puzzle is not `solved`. This will involve modifying the existing `Plot Point Completion Strategy (v2)` to include a puzzle gate check.
    *   **`questforge/templates/admin/state_viewer.html`:** Enhance this admin tool to clearly display the `active_puzzles` section of `GameState.state_data`, including puzzle status, attempts, and any associated AI logs.
*   **Cline AI Agent's Actions:**

    2.  `replace_in_file` to modify `handle_player_action()` in `socket_service.py` to integrate puzzle resolution and gating logic, guarded by `ENABLE_PUZZLES`.
    3.  `replace_in_file` to update `state_viewer.html` to display puzzle state.
    4.  `write_to_file` to create a new Memory Bank document (`memory-bank/puzzle_mechanic_phase2_plan.md`).
*   **Testing (Cline's Responsibility):**

    6.  Simulate player actions that *should not* solve puzzles and verify that plot points remain blocked.
    7.  Verify AI logs for puzzle resolution are correctly generated and visible in the admin viewer.

#### Phase 4: "Skip" / "Fail-Forward" Mechanics

**Goal:** Implement the ability for players to bypass puzzles with consequences, maintaining narrative flow.

*   **Changes:**
    *   **Puzzle Definition (in `Campaign` / `GameState.state_data`):** Add `skip_option: true/false` and `skip_consequences` fields.
    *   **`questforge/templates/game/play.html` & `questforge/static/js/socketClient.mjs`:** Add a "Skip Puzzle" button/option that appears after configurable conditions (e.g., N failed attempts).
    *   **`questforge/services/socket_service.py`:** Implement a new SocketIO event handler (e.g., `handle_skip_puzzle`) that:
        *   Checks if the puzzle is skippable.
        *   Applies `skip_consequences` to `GameState.state_data`.
        *   Marks the puzzle as "bypassed" or "solved" and allows its associated plot point to complete.
    *   **`questforge/utils/prompt_builder.py`:** Update `build_response_prompt()` to instruct the AI to narrate the consequences of skipping a puzzle.
