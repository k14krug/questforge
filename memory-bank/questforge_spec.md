QuestForge Application Specification v4.0
1. Overview
QuestForge is a web application designed to create and play AI-generated cooperative role-playing games (RPGs). The platform utilizes a Python-based backend (e.g., Flask) with Socket.IO for real-time communication. It leverages a tiered system of AI language models to generate narrative content, campaign structures, and in-game responses. A key feature is the dynamic action resolution system, where character skills and simulated dice rolls determine the outcome of player actions. Campaigns are built from “templates,” and gameplay occurs in a rich, browser-based interface managed by a customizable AI Game Master (GM). The core focus is on providing a deep, mechanically engaging, and narratively consistent experience.
2. Core Modules
2.1. User Authentication Module
	• Handles user registration, login, profiles, and secure password management using bcrypt hashing.
	• User profiles store generated character backstories for future reference.
2.2. Template Module
	• Provides a CRUD interface for creating, reading, updating, and deleting campaign templates.
	• Templates define the foundational guidance for AI generation, including genre, core conflict, and world description.
	• Includes a field for AI Game Master "Persona" (e.g., The Chronicler, The Witty Trickster), setting the default narrative style.
	• Defines a list of Core Skills for the campaign (e.g., ["Athletics", "Stealth", "Persuasion", "Investigation", "Arcana"]) that will be used for skill checks.
2.3. Game Management Module
	• Allows users to create new games from a template, overriding settings like the AI GM Persona and selecting AI models.
	• The Game model links the creator, template, and players.
	• The Game model contains a settings JSON field to store game-specific options, including {"enable_visual_dice_roller": true}. This is set at game creation.
	• The GamePlayer association stores player-specific data: character name, description, AI-generated backstory, a URL to their character portrait, "Ready" status, and a character_sheet.
	• character_sheet: A JSON object holding the character's stats and skills (e.g., {"skills": {"Stealth": 3, "Persuasion": -1}}), generated by the AI during character creation.
	• The Game model’s settings JSON field stores session and campaign pacing preferences, e.g., {"expected_session_length_minutes": 120, ...}
2.4. Campaign Structure Module & The Campaign Charter
	• Upon game start, this module generates the "Campaign Charter," a structured, immutable JSON object that serves as the foundational document for the campaign.
	• Charter Components: 
		○ Core Conflict & Ultimate Goal: The central problem and resolution conditions.
		○ Critical Path Objectives: Key plot points players must navigate.
		○ Key World Elements: A definitive list of essential locations, NPCs, items, and their core attributes.
		○ Immutable Rules: Actions the AI GM cannot violate (e.g., "The city of Silverhaven can never fall.").
		○ Interactive Map Layout: A node-based JSON structure of locations and their connections.
		○ NPC Generation: Generates Key NPCs with descriptions and AI-generated portraits.
2.5. AI Game Master Module
	• An AIService layer manages all calls to external AI models.
	• Context Management: Assembles a "context package" for the primary AI model each turn, consisting of: The Campaign Charter, the current GameState, a "Story So Far" Summary, and the last 1-2 raw exchanges.
	• Generation Capabilities: 
		○ Campaign Charter, Player & NPC Images, AI-Assisted Backstory, "Story So Far" Summaries.
		○ Character Sheet Generation: Generates a balanced set of skills for a player's character_sheet based on keywords.
	• Two-Step Action Resolution: Player actions with uncertain outcomes are no longer resolved in a single step. 
		1. Step 1: Check Identification. The AI analyzes a player's action. If a skill check is needed, it responds not with a story, but with a structured JSON object like: {"action_requires_roll": true, "skill": "Persuasion", "difficulty": 15, "narration_prompt": "The guard squints, unconvinced by your story."}.
		2. Step 2: Outcome Narration. After the server resolves the roll, the AI receives the result (e.g., Success/Failure) and the narration_prompt. It then generates the narrative outcome.
	• Core Directives: 
		○ Includes the Directive of Adherence, Narrative Redirection, Deviation Budget, and Post-Campaign Epilogue features as previously defined.
2.6. Game State Tracking Module
	• The GameState model represents the mutable, live state of the game.
	• Role: The Rules Referee. The GameStateService is responsible for executing the game's mechanics.
	• Action Resolution Workflow: 
		1. Receives the AI's JSON request for a skill check.
		2. Looks up the relevant player's skill bonus from their character_sheet in the GamePlayer model.
		3. Simulates a dice roll (e.g., 1d20).
		4. Calculates the final result (dice roll + skill bonus).
		5. Compares the result to the difficulty to determine the outcome (Success/Failure).
		6. Initiates Step 2 of the AI interaction, providing it with the outcome to narrate.
2.7. Real-Time Communication Module
	• Uses Socket.IO for real-time communication in distinct game rooms.
	• Manages events for joining, readying up, starting the game, and submitting actions.
	• When a skill check is initiated, the server broadcasts events to all clients to show the roll request, the dice roll simulation, and the final result before the AI's narrative response arrives.
3. AI Model Management & Economy
3.1. Tiered Model Usage
	• Primary Models (Creative Core): State-of-the-art models (e.g., GPT-4o) used for high-creativity tasks: Campaign Charter generation, per-turn narrative responses, and the final epilogue.
	• Secondary Models (Utility & Speed): Faster, lower-cost models (e.g., GPT-3.5 Turbo) used for structured tasks: AI-assisted backstory generation, "Story So Far" summaries, npc_memory condensation, and AI Response Validation checks.
3.2. Model Dictionary
	• A developer-maintained config.json file serves as the single source of truth for available AI models, their tier, API identifiers, and token costs.
3.3. Cost Tracking & Calculation
	• The GameStateService calculates the cost of each AI call using token usage data from the API response and the costs defined in the Model Dictionary.
	• The cost is added to a cumulative_cost field in the Game model. The initial cost of the Campaign Charter is the first value recorded.
4. User Interface (UI) & User Experience (UX) Flow
4.1. Main Application Layout & Navigation
	• A persistent main navigation bar for Dashboard, Templates, and Games.
4.2. Core Application Screens
	• Dashboard, Template Management, Game Management, Lobby Screen.
	• Create Game Screen: Includes a toggle switch for "Enable Visual Dice Roller". This setting is stored in the Game model.
	• “Expected Session Length” input (minutes/hours): Lets the creator define the intended duration for a session. This is passed to the AI GM and used to pace encounters and objectives.
4.3. The "Play" Screen: An In-Depth View The primary interface is composed of panels and a new visual overlay system.
A. Static (Always Visible) Panels:
	• Game Log Panel (Main, Left/Center): Displays the unfolding story. It now includes both narrative from the GM and system messages that clearly state the skill check, the dice roll, the calculation, and the result. 
		○ Example: 
GM: The guard squints, unconvinced by your story. (A Persuasion check is required).
SYSTEM: Roll: 8 + Persuasion(2) = 10 (Difficulty: 15) -> Failure
GM: He scoffs and draws his sword. "I've heard better lies from a goblin."
	• Action Input Panel (Bottom): Persistent text input for player actions.
	• Game Status Header (Top): Shows campaign title, GM Persona, summary button, and campaign cost.
B. The Information Panel (Right Side, Tabbed Interface):
	• Tab 1: World & Map: Interactive map where clicking a location populates the action input.
	• Tab 2: Party & NPCs: 
		○ Party View: Now prominently displays each player's Character Sheet, showing their core skills and bonuses.
		○ NPC View: Shows known NPCs with portraits and condensed memory.
	• Tab 3: Objectives & Lore: Quest log and discovered documents.
	• Tab 4: Comms & Chat: Player-to-player text chat.
C. Visual Overlays:
	• Visual Dice Roller: If enabled in the game settings, when a skill check is initiated, a modal overlay appears showing a 3D die rolling, settling on a number, and displaying the final calculation. This provides visual excitement and transparency for the mechanical outcome before the narrative result is delivered.
5. Administrative & History Tools
	• Players can view a full, non-interactive history of completed games.
	• Admin pages allow for inspecting raw game state, charters, and application management.
